## Incertidumbre de Admin que debe comprobarse primero

La fuente instalada de Django5.2.17 muestra que GroupAdmin hereda el flujo de ModelAdmin: comprueba has_change_permission, valida el formulario y guarda dentro de una transacción. save_model llama a obj.save; un UPDATE puede esperar una fila. No hay en ese camino una comprobación explícita nueva del permiso después de esa espera SQL.

Esto es una **pregunta de fuente, no un fallo reproducido**. El middleware del proyecto sí comprueba cuenta, documentos y MFA antes de la vista; no se omite una ruta por estar autenticada ni se confunde ese control inicial con una prueba de revocación durante espera. Se priorizan dos diagnósticos finitos —control y permiso retirado— de un POST nativo sobre un Group sintético sin miembros ni permisos. Primero debe demostrarse el bloqueo PostgreSQL, la autoridad inicialmente válida y el resultado real. No se modifica Django ni la aplicación por esta observación estática.

El protocolo específico se fijará antes de ejecutarlos; cualquier corrección posterior dependerá del resultado y conservará controles, auditoría y transacciones. Esta prioridad aplica el criterio de riesgo de S09 y no amplía las familias del contrato.
