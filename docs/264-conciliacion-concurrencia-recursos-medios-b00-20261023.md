## Contraste con el estado local

Se consultaron metadatos de distribuciones instaladas, sin iniciar clientes o servicios: Celery 5.6.3, Pillow 12.3.0, redis-py 6.4.0, Boto3 1.43.108, Ruff 0.16.10 y pip-audit 2.10.1. El kernel comunicado por uname en el host local es 5.14.0-570.58.1.el9_6.x86_64. Estos datos no describen necesariamente procesos de una ejecución anterior, el runtime de una imagen o producción. La captura Boto3 corresponde a 1.43.111 y no selecciona opciones efectivas por coincidir el nombre del SDK.

`config/settings.py` declara JSON para mensajes Celery, resultados ignorados y límites de 120/90 segundos. No se observó entrega de tareas, duplicados, reinicios o efecto de esos límites en este corte. Acuse tardío, prefetch, reintentos y deduplicación del worker no sustituyen idempotencia y transacciones del negocio en PostgreSQL. Un ping Redis o una conexión obtenida de un pool tampoco acredita ese recorrido.

El código de `decode_image` en `apps/mediafiles/services.py` impone formatos estáticos JPEG/PNG/WebP, un límite declarado de 40 megapíxeles, verify, reapertura, load, orientación EXIF y conversión RGB. Esa inspección es coherente con distinguir identificación y decodificación, pero no revalida el pipeline ni demuestra por sí sola eliminación de todos los metadatos o uso acotado de recursos. No se alteraron formatos, límites o derivados por leer Pillow; B15 conserva preferencias explícitas, sin inferencia física o biometría.

Ruff está configurado para py312, longitud 100 y reglas E4/E7/E9/F/I; las dos excepciones F821 de fragmentos históricos se conservan con su explicación. El runner local contiene una invocación Ruff sobre el proyecto. Se inspeccionaron esos archivos: no se ejecutó lint ni se adoptaron opciones para ignorar resultados o aplicar correcciones. La lectura de pip-audit tampoco ejecutó una auditoría de vulnerabilidades ni autoriza aceptar dry-run o un código de salida suprimido como resultado limpio.

Las estadísticas cgroup y los eventos OOM requieren identidad del proceso, alcance jerárquico e intervalo correlacionados para atribuir una causa. La documentación y la versión del kernel observada ahora no prueban la causa del controlador 293. La aceptación del controlador 296 y el cierre local B07 se conservan; no se repiten cargas ni se cambian recursos.
